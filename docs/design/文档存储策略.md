# 文档存储策略

> ⚠️ **本文已更新**。主设计见 [`Agora产品设计方案.md`](./Agora产品设计方案.md) §2.1。  
> 早期版本描述的 `agora-data/` 方案已废弃。

## 背景

用户提出文档不应直接存入数据库，且各项目文档应存在各自仓库内，而非 Agora 运行时目录。

## 决策（v0.2）

### 核心原则：索引，不存储

- **文档内容**在各项目仓库内（如 `docs/design/`、`docs/dev_note/`）
- **Agora DB** 只存元数据索引：`type`、`title`、`file_path`、`tags`
- 读取内容时根据 `file_path` 用 `os.ReadFile` 只读访问
- 创建/删除文档 API **不写文件、不删文件**，只操作索引

### Agora 自身文档

Agora 项目文档存在仓库根目录 `docs/` 下，作为源码一部分：

```
docs/
├── design/
├── dev_note/
├── changelog/    # 规划
└── summary/      # 规划
```

### 其他项目文档

通过 `.agora.yaml` 声明文档目录，Agora 扫描后写入索引：

```yaml
documents:
  design: docs/design/
  dev-notes: docs/dev_note/
```

### DB 字段

`documents` 表：`id, project_id, type, title, file_path, tags, created_at, updated_at`

`file_path` 指向项目仓库内的实际文件路径。

## 变更文件

- `backend/internal/handler/document.go`：纯元数据 CRUD
- `backend/internal/config/config.go`：移除 `AGORA_DATA_DIR`
- 删除 `agora-data/` 目录
