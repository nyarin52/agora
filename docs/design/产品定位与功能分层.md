# 产品定位与功能分层

## 背景

用户最初想做项目管理软件，包含：GitHub 集成、第三方依赖管理、Skill 管理、开发文档、Release 一键打开等。一次性范围过大。

## 讨论过程

- Q: 一次性做太多怎么办？
- A: 做减法，先跑通核心闭环，再迭代。
- Q: 如何划分优先级？
- A: Tier 0 = 核心闭环（能跑通的最小版本），Tier 1 = Quick Wins（高价值低成本），Tier 2 = IDE 集成层，Tier 3 = 未来规划。

## 决策

### Tier 0 -- MVP
- 项目注册 + GitHub 一键导入
- Project CRUD
- Release 列表浏览
- Markdown 文档管理（dev_note/changelog/summary/design）
- Skill 注册表 + 项目关联
- Docker Compose 容器化部署
- 可选 Token 鉴权

### Tier 1 -- Quick Wins
- 依赖自动扫描（读 lock 文件）
- 全文搜索跨项目文档和 Skill
- 标签/分类筛选

### Tier 2 -- IDE 集成
- Cursor 深度链接
- 开发上下文恢复
- Release 资产下载

### Tier 3 -- 未来规划
- CLI 工具（devhub push-context）
- CI/CD 可视化
- 开发时间线
- Plugin 系统
