# 技术选型决策

## 背景

用户熟悉 Go，前端不熟悉，要求跨平台容器化部署，需要 Web 管理页面。

## 讨论过程

### Go vs Node.js

- Q: 后端用 Go 还是 Node.js？
- A: Go。理由：
  - go-github 是官方维护的 SDK，成熟度高
  - 单二进制部署，Docker 镜像从 scratch 起，体积 ~15MB
  - CLI 扩展天然优势（Tier 3 需求）
  - 文件操作比 Node 异步 IO 更自然
  - 唯一弱势：octokit（JS SDK）文档更多，但 go-github 足够

### chi vs gin

- 决策：chi。轻量、标准库风格、中间件生态好，不推荐 gin（太多魔法）

### 前端：React + Vite + Tailwind

- React 生态最好，Cursor 写 React 效率最高
- Vite 快（dev server 秒启）
- Tailwind 组件化风格，一致性高
- React Query 管理服务端状态

### 数据库：SQLite（MVP）

- 零配置、单文件、Docker 不需要额外容器
- 后期数据量大迁移到 PostgreSQL

### 设计系统

- 深色主题（Dark mode only）
- Agora 蓝紫渐变（Indigo-Blue）作为主色调
- Surface 灰度系列作为表面色

## 决策

| 层 | 最终选择 |
|----|---------|
| 后端 | Go 1.23 + chi |
| 数据库 | SQLite |
| GitHub SDK | go-github v68 |
| 前端 | React 18 + TypeScript + Vite |
| 样式 | Tailwind CSS v3 |
| 状态 | React Query v5 |
| 图标 | Lucide React |
| 容器 | Docker Compose（Nginx + Go + 前端） |
